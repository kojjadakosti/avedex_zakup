# Проверка готовности ПАНДЫ к переносу

Локальная Docker-инфраструктура разрабатывается в `infra/local-stack`. **Не запускать перенос на действующую базу.** Полного baseline бизнес-схемы в GitHub нет.

1. `read-only-inventory.sql`: собирает безопасные сводные показатели для сверки исходной и новой базы. Не читает ключи и персональные строки.
2. `transfer-checklist.md`: порядок копирования БД, пользователей, фотографий и ключей, а затем переключения системы.
3. `../supabase/disable-obsolete-cloud-cron.sql`: отключение трёх сетевых заданий исключительно в восстановленной базе, до её подключения к интернету.
4. `../scheduler/`: подготовленный, по умолчанию выключенный планировщик для новой установки.

Рабочая ПАНДА, Vercel и действующий Supabase при подготовке файлов остаются без изменений.

5. `restore-platform-test.sh`: импорт защищённых файлов официального экспорта только в пустую тестовую БД с транзакционной проверкой до COMMIT.
6. `test-restore-guards.sh`: тесты защитных отказов и скрытия SQL-ошибок с имитацией psql, без обращения к реальной БД.

7. `../../scripts/prepare-restore-dump.mjs`: защищённая побайтовая копия SQL-файлов, исключает только два пустых блока векторного Storage; оригинал остаётся неизменным.
8. `../../scripts/check-restore-system-copy.mjs`: read-only аудит всех COPY-целей в системных схемах Auth, Storage и Realtime: таблицы, столбцы и права INSERT у роли восстановления.
